# 匯入銀行明細

fava 的 Import 頁可以把銀行下載的明細轉成交易。image 內建一個 importer，`beancount_agent_api.importers.statement` 的 `StatementImporter`。每家銀行匯出的格式不同，它依檔案類型與標題列認出下表的兩種格式：

| 格式 | 檔案 | 欄位 | 檢查完整 |
| --- | --- | --- | --- |
| 單一金額欄 | xlsx，第一列是標題，第二列是欄位名稱，由舊到新 | 交易日、帳務日、摘要、金額、餘額、備註；金額有正負號 | 最後一列「共 N 筆資料 資料日期：…」 |
| 提出、存入分欄 | csv（UTF-8），第一列是帳號與帳戶種類，欄位名稱之前有「筆數」與查詢期間，由新到舊 | 交易日期、帳務日期、說明、提出、存入、餘額、交易資訊、備註；空的一邊寫「−」，金額有千分位逗號 | 欄位名稱之前的「筆數：N 筆」，以及最後的提出、存入各自的總金額與筆數 |

欄位或標題列不同的檔案它不認得。沒有逐列餘額的明細（例如信用卡帳單）也不適用，因為它靠逐列餘額檢查明細完整並寫出每天的斷言。格式在 `beancount_agent_api.importers.layouts` 讀取，其他格式目前沒有支援。

## 設定

帳本資料夾（容器的 `/ledger`）放一個設定檔，例如 `importers.py`。`title` 照抄匯出檔第一列的文字（csv 是第一列第一格）；前後的空白不算，中間的空白要相同。importer 只認標題相同的檔案。每個帳戶各建一個 `StatementImporter`：

```python
from beancount_agent_api.importers.statement import StatementImporter

CONFIG = [
    StatementImporter(
        "Assets:Bank:Checking",
        title="<匯出檔第一列的標題>",
        rules=[
            ("存款息", "Income:Interest"),
            ("劃撥轉帳", "Assets:Broker:Stocks"),
        ],
        fallback_account="Expenses:Uncategorized",
    ),
]
```

主帳本加上兩個 fava 選項。路徑相對於主帳本所在的資料夾：

```beancount
2000-01-01 custom "fava-option" "import-config" "importers.py"
2000-01-01 custom "fava-option" "import-dirs" "import"
```

`import-dirs` 是上傳的檔案存放的資料夾，fava 上傳時會自己建立，所以容器的使用者要能寫入主帳本所在的資料夾。

## 轉換規則

- 每一列明細轉成一筆交易。日期取交易日（期）的日期，因為銀行的逐列餘額照它排序；帳務日（期）不同天時，另存成 `booking-date` metadata。交易說明（narration）用備註，備註空白時用摘要（說明）。提出、存入分欄的格式，說明後面接上交易資訊（對方的銀行代號與帳號）。
- `rules` 依序比對摘要（說明）與備註，第一個出現在文字裡的字串決定另一邊的帳戶。都對不到時記到 `fallback_account`，flag 是 `!`，在匯入頁看得出來。`fallback_account` 要在帳本裡 `open`。
- 每筆交易帶 `statement-id` metadata，內容是交易時間、金額與餘額。
- 每個有交易的日子，隔天寫一筆 `balance` 斷言，金額是銀行那天最後的餘額；明細第一天另寫一筆期初斷言。匯出當天之後可能還有交易，所以匯出日不寫。提出、存入分欄的格式沒有匯出時間，以查詢期間的結束日當作匯出日。
- 明細的每一列都要接得上前一列的餘額，筆數與總額要等於檔案寫的筆數與總額。不符合時整份檔案不轉換，匯入失敗。
- 交易的第一個 posting 是這個帳戶。去重複靠它分辨哪些是這個帳戶自己匯入的交易，所以編輯匯入的交易時不要調換 posting 的順序。

## 第一次匯入

期初斷言要和帳上的餘額相同。帳上在明細第一天之前少記或多記時，在那天前一天加一筆 `pad`，例如明細從 6/1 開始：

```beancount
2026-05-31 pad Assets:Bank:Checking Equity:Balance-Adjustment
```

帳上同一期間有手寫、和銀行不同的 `balance` 時，刪掉它，以匯入的斷言為準。之後的明細從上一份的最後一天接著下載，或和上一份重疊，就不用再加 `pad`。兩份明細之間少了幾天時，期初斷言會失敗，這時補下載缺的日子，不要加 `pad`。

## 重複的交易

fava 匯入頁存檔時，跳過標成重複的項目，每一項都可以在匯入頁切換。

- 這個帳戶匯入過、帶相同 `statement-id` 的交易，以及同一天、同帳戶、同金額的 `balance`，標成重複。
- 其他交易（手動記的、經 agent API 記的、從另一個帳戶的明細匯入而轉到這個帳戶的），在這個帳戶的金額合計和明細的一列完全相同、日期相差 7 天以內時，標成重複。一筆只抵一列，日期最近的先配對，所以同一天兩筆同額的明細要帳上有兩筆才都標成重複。
- 配對沒抓到或配錯時，那一天之後的第一筆 `balance` 斷言會失敗。斷言失敗的日子就是要檢查的地方。
- 帳上 `pad` 補出的交易不參與配對。
- 下載的明細最好包含上一份的最後幾天。被手記抵掉的那一列不會存進帳本，下一份明細如果不含那一列，同一筆手記可能再抵掉 7 天內另一列同額的交易。
- 這個帳戶的進出只靠匯入記，最不會出錯。

### 自己帳戶之間的轉帳

兩個帳戶都用 importer 匯入時，轉帳在兩份明細各有一列。兩邊的 `rules` 各加一條，用對方帳號（明細裡出現的寫法）對到對方的帳戶，例如：

```python
StatementImporter("Assets:Bank:Checking", ..., rules=[("999-000123456789", "Assets:Bank:Savings")], ...)
StatementImporter("Assets:Bank:Savings", ..., rules=[("(999)0000111", "Assets:Bank:Checking")], ...)
```

先匯入的那份把轉帳記成兩個帳戶之間的交易。後匯入的那份，同金額、7 天內的那列標成重複，兩邊的斷言都會檢查。先匯入時轉帳記到 `fallback_account` 的，先把另一邊改成對方的帳戶，再匯入另一份。銀行對轉入與轉出可能寫不同的帳號寫法（例如中間遮成 `***`），規則要涵蓋兩種。

兩家銀行把同一筆轉帳記在不同天時（例如晚上的跨行轉帳），一筆交易只有一個日期，後匯入那個帳戶在兩個日期之間的斷言會失敗。這時改用在途帳戶（例如 `Assets:Transfer`）：先匯入的那筆把對方帳戶改成在途帳戶，後匯入時在匯入頁取消那一列的重複標記，對方帳戶也改成在途帳戶，兩邊各記在自己入帳的那天。

## 股票交割

交割款在交割日（成交後第 2 個營業日）才進出帳戶，匯入的日期就是交割日。在成交日手記扣款時，即使配對把匯入的那列標成重複，成交日到交割日之間每一天的斷言仍會失敗，因為帳上比銀行早扣了錢。兩種不會出錯的記法：

- 這個帳戶的進出只靠匯入記。匯入時在匯入頁把另一邊改成持股帳戶，填上成本與手續費；持股的日期是交割日。
- 成交日記「持股 / 應付交割款」（例如 `Liabilities:Broker:Payable`），規則把 `劃撥轉帳` 對到應付交割款，交割日匯入時沖掉；持股的日期是成交日。

已經在成交日手記扣款時，把那筆的日期改成交割日。

## 已知限制

- 單一金額欄的明細沒有帳號。同一家銀行的兩個帳戶匯出的標題相同時，兩個 importer 都認得這份檔案，匯入頁要選一個。
- 明細只有現金的進出。股票的股數與成本、賣出時的損益要在匯入頁或帳本裡補。
- 手記時把一列明細拆成兩筆交易（例如成本與手續費分開記），金額對不上，不會標成重複；斷言會在那天之後失敗。
- xlsx 只讀第一個工作表，而且只支援 inline 字串與數字儲存格；csv 只讀 UTF-8。銀行改了格式時 importer 不認得這份檔案。
